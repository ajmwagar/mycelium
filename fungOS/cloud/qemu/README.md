# Nested workload smoke test

The fungOS **host** uses systemd, Mycelium and Shroud. Workload microVMs do not
enroll in Mycelium: their image is minimal application userspace plus Shroud's
existing initramfs. OCI conversion remains owned by `shroudoci`, not Mycelium
or a new fungOS image format.

Verified on Agora's persistent fungOS QEMU guest on 2026-10-05. Its running
kernel `7.0.0-34-generic` required matching KVM/AMD and bridge modules. The QEMU
CPU exposed `svm`; module loading produced a real `/dev/kvm`. The test-only
`modules.conf` is AMD-specific and must not be installed on Intel or ARM hosts.
Provision matching modules (including dependencies), run `depmod`, and verify
KVM and TUN devices. Never substitute host modules for a different guest kernel.

## Prepare outside the runtime host

On Agora, the existing `shroudoci` converted this pinned OCI input:

```sh
shroudoci extract \
  docker.io/library/busybox@sha256:bdf57e528e45e4433820e045b29b4597825a1c9e38353532d90a01445013f82e \
  /absolute/new/output \
  --process-arg /bin/sh --process-arg=-c \
  --process-arg='echo FUNGOS_MICROVM_OK; uname -m; sleep 120'
shroudoci manifest /absolute/new/output --name fungos-smoke
```

No credentials, Mycelium binary, systemd or second Shroud daemon is added to
this workload image. The workload never changes physical devices. Build tools
stay on the builder; only prepared artifacts go to the runtime host.

## Native host setup and execution

Install the declared cloud runtime tools, including `dnsmasq-utils` (lease
release) and `curl` (the existing Firecracker API adapter). Stage Shroud and
Firecracker through signed package verification. Provision the verified inner
kernel at `/var/lib/shroud/kernels/vmlinux` and the two prepared image files
under `/var/lib/shroud/images/fungos-smoke`; compare their digests after copying.
The local `prepared://` fixture is manually verified staging, not artifact-store
admission. Production uses Shroud's existing digest-pinned `rootfs:` path.

Install `../shroud.service`, the `10-smoke.conf` drop-in, and
`microvm-smoke.toml` under their corresponding systemd/config directories.
The test disables NAT and host-published workload ports; it retains Shroud's
bridge-scoped managed DHCP. No host LAN or DigitalOcean networking is changed.

```sh
systemd-analyze verify /etc/systemd/system/shroud.service
systemctl daemon-reload
systemctl enable --now shroud
printf '%s\n' '{"action":"start","vm":"fungos-smoke"}' |
  socat -T 20 - UNIX-CONNECT:/var/lib/shroud/control.sock
grep -F FUNGOS_MICROVM_OK /var/lib/shroud/logs/fc_fungos-smoke.log
printf '%s\n' '{"action":"stop","vm":"fungos-smoke"}' |
  socat -T 10 - UNIX-CONNECT:/var/lib/shroud/control.sock
```

The execution marker and `x86_64` were observed from the inner VM's serial log,
not generated by the host. Shroud reported a running Firecracker process with
one vCPU, 128 MiB memory, and guest IP `172.16.0.100`. Its health checks are
disabled for this finite smoke workload; reported `ready` is not an application
health proof. All five independent edge units remained active. Config autostart
is false, so rebooting the host must not spontaneously launch the test workload.

Native stop succeeded. After reboot, `/dev/kvm` and all six systemd services
returned, while the workload list was empty as intended. Explicitly starting
the same microVM emitted the marker again; stopping it left no Firecracker
process. No failed systemd units remained. Agora's host Shroud, GPU ownership,
and production Beachhead/Bob resources were not changed by this test.
